#k8s 
## 개요

Kubernetes 클러스터는 컨트롤 플레인(마스터 노드)과 워커 노드로 구성됩니다. 이 가이드에서는 두 노드 유형의 운영 절차, 마스터 노드에서 컨테이너를 실행하는 방법, 그리고 이와 관련된 고려사항에 대해 자세히 설명합니다.

클러스터의 안정성을 위해 일반적으로 마스터 노드에서는 워크로드를 실행하지 않도록 설계되었지만, 테스트 환경이나 자원 제약이 있는 상황에서는 마스터 노드에서도 컨테이너를 실행해야 할 수 있습니다. 이 가이드는 이러한 시나리오에 대한 안전한 접근 방법을 제공합니다.

## 마스터 노드(컨트롤 플레인)와 워커 노드 아키텍처

### 마스터 노드(컨트롤 플레인) 구성요소

마스터 노드는 Kubernetes 클러스터의 "두뇌" 역할을 하며, 다음 핵심 구성요소로 이루어져 있습니다:

- **kube-apiserver**: 클러스터의 API 서버로, 모든 관리 작업의 진입점
- **etcd**: 클러스터의 모든 상태를 저장하는 분산 키-값 저장소
- **kube-scheduler**: 새로 생성된 파드를 노드에 할당하는 스케줄러
- **kube-controller-manager**: 컨트롤러 프로세스를 실행하는 컴포넌트
- **cloud-controller-manager**: (선택적) 클라우드 제공업체와 상호작용하는 컴포넌트

### 워커 노드 구성요소

워커 노드는 실제 애플리케이션 컨테이너를 실행하는 노드로, 다음 구성요소를 포함합니다:

- **kubelet**: 노드에서 실행되는 에이전트로, 컨테이너가 파드 내에서 실행되도록 관리
- **kube-proxy**: 네트워크 규칙을 유지관리하여 파드 간 통신 지원
- **컨테이너 런타임**: 컨테이너를 실행하는 소프트웨어(예: containerd, CRI-O)

## 마스터 노드 운영 절차

### 1. 마스터 노드 설치 및 초기화

### 사전 요구사항

- 최소 2 CPU, 2GB RAM, 20GB 디스크 권장
- Linux OS (Ubuntu, CentOS 등)
- 방화벽에서 필요한 포트 개방(6443, 2379-2380, 10250-10252 등)

### 설치 절차

```bash
Copy# 1. 컨테이너 런타임 설치 (containerd 예시)
cat <<EOF | sudo tee /etc/modules-load.d/containerd.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

cat <<EOF | sudo tee /etc/sysctl.d/99-kubernetes-cri.conf
net.bridge.bridge-nf-call-iptables  = 1
net.ipv4.ip_forward                 = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF

sudo sysctl --system

# containerd 설치
sudo apt-get update && sudo apt-get install -y containerd
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml
sudo systemctl restart containerd

# 2. kubeadm, kubelet, kubectl 설치
sudo apt-get update && sudo apt-get install -y apt-transport-https ca-certificates curl

sudo curl -fsSL <https://pkgs.k8s.io/core:/stable:/v1.30/deb/Release.key> | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] <https://pkgs.k8s.io/core:/stable:/v1.30/deb/> /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl

# 3. swap 비활성화 (필수)
sudo swapoff -a
sudo sed -i '/ swap / s/^\\(.*\\)$/#\\1/g' /etc/fstab

# 4. 클러스터 초기화
sudo kubeadm init --pod-network-cidr=10.244.0.0/16

# 5. 사용자 환경 설정
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# 6. 네트워크 플러그인 설치 (예: Calico 또는 Flannel)
kubectl apply -f <https://raw.githubusercontent.com/flannel-io/flannel/master/Documentation/kube-flannel.yml>

```

### 2. 마스터 노드 백업 및 복원

### etcd 백업

```bash
Copy# etcd 스냅샷 생성
sudo ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \\
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \\
  --cert=/etc/kubernetes/pki/etcd/server.crt \\
  --key=/etc/kubernetes/pki/etcd/server.key \\
  snapshot save /tmp/etcd-backup-$(date +%Y-%m-%d-%H-%M-%S).db

# 인증서 백업
sudo cp -r /etc/kubernetes/pki /tmp/k8s-pki-backup-$(date +%Y-%m-%d-%H-%M-%S)

```

### etcd 복원

```bash
Copy# etcd 서비스 중지
sudo systemctl stop kubelet
sudo docker stop $(sudo docker ps -q --filter ancestor=k8s.gcr.io/etcd:3.4.13-0)

# 데이터 디렉토리 백업 및 정리
sudo mv /var/lib/etcd /var/lib/etcd.old

# 스냅샷으로부터 복원
sudo ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \\
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \\
  --cert=/etc/kubernetes/pki/etcd/server.crt \\
  --key=/etc/kubernetes/pki/etcd/server.key \\
  --data-dir=/var/lib/etcd \\
  --initial-cluster=master=https://127.0.0.1:2380 \\
  --initial-advertise-peer-urls=https://127.0.0.1:2380 \\
  --name=master \\
  snapshot restore /tmp/etcd-backup.db

# 서비스 재시작
sudo systemctl start kubelet

```

### 4. 고가용성 마스터 노드 구성 (HA 설정)

### Stacked etcd 토폴로지 (권장)

이 설정에서는 각 컨트롤 플레인 노드에 etcd 멤버가 함께 실행됩니다.

```bash
Copy# 로드 밸런서 설정 후 첫 번째 마스터 노드 초기화
sudo kubeadm init --control-plane-endpoint "LOAD_BALANCER_DNS:LOAD_BALANCER_PORT" \\
    --upload-certs \\
    --pod-network-cidr=10.244.0.0/16

# 추가 마스터 노드 조인 (kubeadm init 출력에서 제공된 명령어 사용)
sudo kubeadm join LOAD_BALANCER_DNS:LOAD_BALANCER_PORT \\
    --token <token> \\
    --discovery-token-ca-cert-hash sha256:<hash> \\
    --control-plane \\
    --certificate-key <certificate-key>

```

### 외부 etcd 토폴로지

etcd를 별도의 노드에서 실행하는 고급 설정입니다.

```bash
Copy# etcd 클러스터 먼저 설정한 후
# 마스터 노드 초기화 (외부 etcd 지정)
sudo kubeadm init --control-plane-endpoint "LOAD_BALANCER_DNS:LOAD_BALANCER_PORT" \\
    --upload-certs \\
    --pod-network-cidr=10.244.0.0/16 \\
    --external-etcd-endpoints=https://ETCD_0_IP:2379,https://ETCD_1_IP:2379,https://ETCD_2_IP:2379 \\
    --external-etcd-cafile=/path/to/etcd/ca.crt \\
    --external-etcd-certfile=/path/to/etcd/client.crt \\
    --external-etcd-keyfile=/path/to/etcd/client.key

```

## 워커 노드 운영 절차

### 1. 워커 노드 구성

### 사전 요구사항

- 최소 1 CPU, 2GB RAM, 20GB 디스크 권장
- Linux OS (Ubuntu, CentOS 등)
- 마스터 노드와 네트워크 연결 (포트 6443 접근 가능)

### 설치 절차

```bash
Copy# 1. 컨테이너 런타임 설치 (마스터 노드와 동일)
# 생략...

# 2. kubeadm, kubelet, kubectl 설치 (마스터 노드와 동일)
# 생략...

# 3. swap 비활성화 (필수)
sudo swapoff -a
sudo sed -i '/ swap / s/^\\(.*\\)$/#\\1/g' /etc/fstab

# 4. 클러스터 조인
# 마스터 노드에서 토큰 생성
# kubectl create token 명령어 사용 (마스터 노드에서 실행)
```

### 2. 워커 노드 관리

### 노드 레이블 관리

```bash
Copy# 노드에 레이블 추가
kubectl label nodes <node-name> key=value

# 예: 노드에 역할 지정

# 노드 레이블 확인
kubectl get nodes --show-labels

```

### 노드 테인트(taint) 관리

```bash
Copy# 노드에 테인트 추가 (특정 워크로드만 실행되도록)
kubectl taint nodes <node-name> key=value:NoSchedule

# 테인트 제거
kubectl taint nodes <node-name> key:NoSchedule-

```

### 노드 드레이닝(Draining)

유지보수 전 노드의 워크로드를 다른 노드로 이전합니다.

```bash
Copy# 노드 드레인
kubectl drain <node-name> --ignore-daemonsets --delete-local-data

# 유지보수 완료 후 노드 다시 스케줄 가능하게 설정
kubectl uncordon <node-name>

```

### 노드 차단(Cordon)

새로운 파드가 노드에 스케줄되지 않도록 합니다.

```bash
Copy# 노드 차단
kubectl cordon <node-name>

# 노드 차단 해제
kubectl uncordon <node-name>

```

## 마스터 노드에서 워크로드 실행하기

기본적으로 Kubernetes는 마스터 노드에 워크로드를 스케줄링하지 않도록 테인트(taint)를 설정합니다. 이는 컨트롤 플레인의 안정성을 보장하기 위한 것입니다.

### 1. 마스터 노드 테인트(Taint) 확인

```bash
Copy# 마스터 노드의 테인트 확인
kubectl describe node <master-node-name> | grep Taints

```

일반적으로 마스터 노드에는 다음과 같은 테인트가 설정되어 있습니다:

```
Taints: node-role.kubernetes.io/master:NoSchedule

```

또는 더 최신 버전에서는:

```
Taints: node-role.kubernetes.io/control-plane:NoSchedule

```

### 2. 마스터 노드에서 워크로드 실행을 위한 테인트 제거

```bash
Copy# 모든 마스터 노드의 테인트 제거
kubectl taint nodes --all node-role.kubernetes.io/master-

# 또는 최신 버전의 경우
kubectl taint nodes --all node-role.kubernetes.io/control-plane-

# 특정 마스터 노드의 테인트만 제거
kubectl taint nodes <master-node-name> node-role.kubernetes.io/master:NoSchedule-

```

### 3. 특정 워크로드만 마스터 노드에서 실행하기

테인트를 완전히 제거하지 않고 특정 워크로드만 마스터 노드에서 실행하려면, 해당 파드에 톨러레이션(toleration)을 추가하면 됩니다.

```yaml
CopyapiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      tolerations:
      - key: "node-role.kubernetes.io/master"
        operator: "Exists"
        effect: "NoSchedule"
      # 또는 최신 버전의 경우
      - key: "node-role.kubernetes.io/control-plane"
        operator: "Exists"
        effect: "NoSchedule"
      containers:
      - name: nginx
        image: nginx:1.7.9
        ports:
        - containerPort: 80

```

### 4. 마스터 노드 전용 워크로드 설정

마스터 노드에만 특정 워크로드를 실행하려면, 노드 선택자(nodeSelector)나 노드 어피니티(nodeAffinity)를 사용합니다.

```yaml
CopyapiVersion: apps/v1
kind: Deployment
metadata:
  name: master-only-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: master-app
  template:
    metadata:
      labels:
        app: master-app
    spec:
      tolerations:
      - key: "node-role.kubernetes.io/master"
        operator: "Exists"
        effect: "NoSchedule"
      nodeSelector:
        node-role.kubernetes.io/master: ""
      containers:
      - name: app
        image: myapp:1.0

```

### 5. 마스터 노드에 테인트 다시 적용하기

워크로드 배포 테스트 후 다시 테인트를 적용하여 마스터 노드를 보호할 수 있습니다.

```bash
Copy# 특정 마스터 노드에 테인트 다시 적용
kubectl taint nodes <master-node-name> node-role.kubernetes.io/master=:NoSchedule

# 모든 마스터 노드에 테인트 다시 적용
kubectl get nodes -l node-role.kubernetes.io/master= -o name | xargs -I{} kubectl taint {} node-role.kubernetes.io/master=:NoSchedule

```

## 운영 시 고려사항 및 모범 사례

### 마스터 노드에서 워크로드 실행 시 고려사항

1. **리소스 경쟁**
    - 마스터 노드의 컨트롤 플레인 구성요소는 안정적인 리소스 공급이 필요합니다
    - 리소스 제한(limits)과 요청(requests)을 명확히 설정하여 컨트롤 플레인 리소스 고갈 방지
    - 마스터 노드에 배포하는 워크로드 수 제한
2. **컨트롤 플레인 안정성**
    - 중요하지 않은 워크로드만 마스터 노드에 배포
    - 상태 비저장(stateless) 애플리케이션 우선 배포
    - 모니터링과 알림을 강화하여 마스터 노드 리소스 사용량 관찰
3. **마스터 노드 워크로드 적합성**
    - 가벼운 모니터링 에이전트, 로깅 솔루션 등의 클러스터 관리 워크로드에 적합
    - 높은 가용성이 필요하지 않은 개발 환경이나 테스트 환경에 적합
    - 프로덕션 환경에서는 가급적 워커 노드만 사용 권장

### 노드 관리 모범 사례

1. **리소스 관리**
    - 노드별 적절한 파드 밀도 유지
    - 시스템 데몬과 쿠버네티스 구성 요소를 위한 리소스 예약
    - 노드 자동 확장 구성(필요 시)
2. **업그레이드 전략**
    - 마스터 노드 먼저 업그레이드 후 워커 노드 업그레이드
    - 워커 노드는 롤링 업그레이드 방식으로 진행
    - 중요 변경 전 항상 etcd 백업 수행
3. **모니터링 및 로깅**
    - 노드 수준 메트릭 수집(CPU, 메모리, 디스크, 네트워크)
    - kubelet, 컨테이너 런타임 로그 모니터링
    - 알림 설정으로 노드 문제 조기 감지
4. **보안 강화**
    - 정기적인 보안 업데이트 적용
    - 불필요한 서비스 비활성화
    - 노드 접근 제한 및 감사 로깅 설정

## 문제 해결 가이드

### 마스터 노드 문제 해결

1. **API 서버 접근 불가**
    
    ```bash
    Copy# API 서버 상태 확인
    sudo systemctl status kube-apiserver
    
    # API 서버 로그 확인
    sudo journalctl -u kube-apiserver
    
    # 인증서 문제 확인
    sudo openssl x509 -in /etc/kubernetes/pki/apiserver.crt -text
    
    ```
    
2. **etcd 문제**
    
    ```bash
    Copy# etcd 상태 확인
    sudo systemctl status etcd
    
    # etcd 멤버 상태 확인
    sudo ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \\
      --cacert=/etc/kubernetes/pki/etcd/ca.crt \\
      --cert=/etc/kubernetes/pki/etcd/server.crt \\
      --key=/etc/kubernetes/pki/etcd/server.key \\
      member list
    
    # etcd 클러스터 건강 상태 확인
    sudo ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \\
      --cacert=/etc/kubernetes/pki/etcd/ca.crt \\
      --cert=/etc/kubernetes/pki/etcd/server.crt \\
      --key=/etc/kubernetes/pki/etcd/server.key \\
      endpoint health
    
    ```
    
3. **스케줄러 또는 컨트롤러 관리자 문제**
    
    ```bash
    Copy# 상태 확인
    sudo systemctl status kube-scheduler
    sudo systemctl status kube-controller-manager
    
    # 로그 확인
    sudo journalctl -u kube-scheduler
    sudo journalctl -u kube-controller-manager
    
    ```
    

### 워커 노드 문제 해결

1. **노드 NotReady 상태**
    
    ```bash
    Copy# 노드 상태 상세 확인
    kubectl describe node <node-name>
    
    # kubelet 상태 확인
    sudo systemctl status kubelet
    
    # kubelet 로그 확인
    sudo journalctl -u kubelet
    
    ```
    
2. **네트워크 문제**
    
    ```bash
    Copy# CNI 플러그인 파드 상태 확인
    kubectl get pods -n kube-system
    
    # 노드 간 연결 테스트
    ping <other-node-ip>
    
    # DNS 테스트
    nslookup kubernetes.default.svc.cluster.local
    
    ```
    
3. **파드 시작 실패**
    
    ```bash
    Copy# 파드 상태 확인
    kubectl describe pod <pod-name>
    
    # 파드 로그 확인
    kubectl logs <pod-name>
    
    # 컨테이너 런타임 로그 확인
    sudo journalctl -u containerd
    
    ```
    

## 결론

Kubernetes 마스터 노드(컨트롤 플레인)와 워커 노드는 각각 고유한 역할을 수행하며, 적절한 운영 절차를 따르는 것이 클러스터의 안정성과 성능을 보장하는 데 중요합니다. 일반적으로 마스터 노드는 클러스터 관리에 집중하고 워커 노드는 애플리케이션 워크로드를 실행하도록 설계되어 있습니다.

그러나 특정 상황에서는 마스터 노드에서도 워크로드를 실행해야 할 필요가 있을 수 있습니다. 이 경우 테인트와 톨러레이션을 이용하여 안전하게 워크로드를 배포할 수 있지만, 항상 컨트롤 플레인의 안정성을 최우선으로 고려해야 합니다.

효과적인 Kubernetes 클러스터 운영을 위해서는 정기적인 백업, 신중한 업그레이드 계획, 포괄적인 모니터링, 그리고 적절한 리소스 관리가 필수적입니다. 이 운영 가이드를 통해 마스터 노드와 워커 노드를 효율적으로 관리하고, 필요한 경우 마스터 노드에서도 안전하게 워크로드를 실행할 수 있기를 바랍니다.
