
Cursor와 같은 AI 코딩 도구는 축복이 될 수도 있고 저주가 될 수도 있다. 잘 작동할 때는 완전한 마법 같지만, 그렇지 않을 때는 마치 취한 어린아이가 코드베이스에서 난장판을 벌이는 것과 같다. 나도 그런 경험이 있다 - AI가 생성한 엉망진창 코드를 보며 직접 코딩하는 게 나았을지 고민하던 순간들. 너무 많은 밤샘 디버깅 재앙을 겪은 후, 마침내 Cursor가 내가 정확히 필요로 하는 것을 매번 제공하도록 하는 방법을 발견했다. 여기 혼돈을 피하고 Cursor의 힘을 활용하는 데 도움이 될 내 실전 경험을 바탕으로 한 전략을 소개한다.

## Cursor가 코드를 망치는 이유 (그리고 해결 방법)
여기 핵심이 있다. Cursor는 마음을 읽는 기계가 아니다. 계획 없이 바로 코딩을 시작하면 원하는 것을 추측하게 만드는데, 이 추측은 끔찍할 정도로 형편없다. 내가 Cursor에게 작업 관리 앱을 만들어달라고 했을 때 맞지 않는 프레임워크들이 조합된 괴물 같은 코드를 받았을 때 이를 뼈저리게 깨달았다. 해결책은 무엇일까? 바로 계획이다 - 정확히 말하면 70%는 계획, 30%는 실행이다. 자세히 알아보자.

## Step 1: 생사가 달린 것처럼 계획하기
예전에 나는 아무 생각 없이 Cursor를 켜고 "앱을 만들어줘"라고 입력하던 사람이었다. 큰 실수였다. 이제 나는 계획을 워크플로우의 기초로 삼고 있으며, 이것은 게임 체인저가 되었다.
### 나의 비밀 무기: ChatGPT Voice
다른 AI를 사용해 Cursor를 길들이는 것이 이상하게 들릴 수 있지만, 내 말을 들어보라. 코딩 전에 ChatGPT Voice를 사용해 내 아이디어를 이야기한다. 내 생각을 말로 표현하는 것이 원하는 바를 명확히 하는 데 도움이 된다. 예를 들어, 작업 관리 앱을 위해 이렇게 말할 수 있다.

"안녕, 작업을 관리하는 앱을 만들고 있어. 사용자가 작업을 추가, 편집, 삭제할 수 있어야 해. 작업을 나열하는 홈페이지, 새 작업을 추가하는 양식, 기존 작업을 편집하는 페이지가 필요해."

ChatGPT Voice는 내가 개요를 스케치하는 데 도움을 주고, 이를 냅킨에 끄적여 놓는다 (그래, 나는 이런 구식 방법을 좋아한다).

작업 앱 계획
- 큰 아이디어: 간단한 작업 관리
- 필수 요소:
    - 작업 추가, 편집, 삭제
    - 모든 작업 보기
- 흐름:
    - 홈페이지: 작업 목록
    - 작업 추가 페이지: 양식
    - 작업 상세 페이지: 편집

이 냅킨 스케치는 내 북극성과 같다. 나와 Cursor가 계속 올바른 방향으로 나아가도록 해준다.

## Step 2: 모든 것을 문서화하기
어렵게 배운 교훈은 AI 코드는 제공하는 컨텍스트만큼만 좋다는 것이다. 문서화를 건너뛰면 Cursor는 어리석은 결정을 내린다 - 한번은 오류 처리가 전혀 없는 백엔드 API를 만들어줬을 때처럼 말이다. 정말 짜증났다.

### 내가 사용하는 도구: CodeGuide
나는 CodeGuide라는 도구를 사용해 두 가지 핵심 문서를 생성한다.

제품 요구사항 문서(PRD): "무엇"에 해당하는 것 - 기능, 사용자 스토리, 예외 상황 기술 스택: "어떻게"에 해당하는 것 - 프레임워크, 라이브러리, 도구

내 작업 앱을 위한 PRD 일부는 다음과 같다.
PRD: TaskMaster
- 목표: 작업을 정말 간단하게 만들기
- 사용자 스토리:
    - 내 작업을 추적하기 위해 작업을 추가하고 싶다
    - 오타를 수정하기 위해 작업을 편집하고 싶다
    - 완료된 작업은 삭제하고 싶다
- 기술 스택:
    - 프론트엔드: React + TypeScript (타입 안정성이 좋다)
    - 백엔드: Node.js + Express (가볍고 빠르다)
    - 데이터베이스: MongoDB (작은 프로젝트에 유연하다)

이 문서들은 Cursor를 위한 내 컨닝 페이퍼다 - 추측할 여지가 없다.

## Step 3: 처음부터 시작하지 않기
백지 상태에서 프로젝트를 시작하는 것은 AI 도구에서는 재앙이다. Cursor는 설정에 어려움을 겪는다 - 파일 구조, 보일러플레이트, 의존성 등. 한번은 깨진 Webpack 구성이 있는 React 프로젝트를 제공받았을 때 이를 깨달았다. 이제 나는 항상 스타터 킷을 사용한다. 내 작업 앱을 위해 다음과 같은 구조의 React + Node.js 킷을 가져왔다.

```
taskmaster/
├── frontend/
│   ├── src/
│   │   ├── components/
│   │   ├── pages/
│   │   └── App.tsx
├── backend/
│   ├── src/
│   │   ├── routes/
│   │   └── server.ts
└── README.md
```

스타터 킷은 Cursor가 뼈대가 아닌 기능에 집중할 수 있게 해준다. 마치 요리사에게 미리 썰어놓은 양파를 주는 것과 같다 - 덜 지저분하고, 더 많은 진전이 있다.

## Step 4: Cursor 올바르게 설정하기
계획, 문서, 스타터 킷이 준비되었나? 좋다. 이제 Cursor에 단 하나의 프롬프트를 입력하기 전에 무대를 설정해야 한다.

1. 프로젝트 루트에 Instructions 폴더를 만든다.
2. CodeGuide 문서를 그곳에 넣는다.
3. Cursor에게 다음과 같이 입력하여 이를 컨텍스트로 사용하도록 한다: "Instructions의 모든 파일을 살펴보고 컨텍스트로 사용해."

이는 마치 Cursor에게 건물을 짓기 전에 청사진을 건네주는 것과 같다. 이 단계를 건너뛰면 문제를 자초하는 것이다.

## Step 5: 프로젝트 규칙의 마법
여기서 마법이 일어난다. Cursor가 내 코드를 망치는 가장 큰 이유는 명확한 규칙을 설정하지 않았기 때문이었다. 규칙 없이는 추측하게 되고 - 그 추측은 종종 틀리다. 한번은 내가 함수형 컴포넌트를 원했을 때 React 클래스 컴포넌트를 제공한 적이 있었다. 정말 답답했다!

### .cursorrules가 왜 형편없었는가
Cursor는 예전에 규칙을 위해 단일 .cursorrules 파일에 의존했지만, 이는 악몽이었다. 모든 지시사항을 하나의 파일에 밀어넣었고, Cursor는 그 중 절반을 무시했다. 확장성이 없었고, AI의 응답은 예측할 수 없었다.

### 프로젝트 규칙 소개 (.mdc 파일)
다행히도 Cursor는 .cursor/rules/ 디렉토리에 있는 .mdc 파일을 사용하는 프로젝트 규칙을 도입했다. 이는 게임 체인저였다. 프로젝트 규칙을 통해 프로젝트의 다른 부분에 대해 특정 지시사항을 설정할 수 있다. 내 작업 앱을 위해 다음과 같은 규칙을 설정했다.

```
taskmaster/
├── .cursor/
│   └── rules/
│       ├── frontend.mdc
│       ├── backend.mdc
```

frontend.mdc
```
Scope: **/*.tsx
Rules:
- 함수형 컴포넌트 + React 훅 사용 (클래스 컴포넌트 금지)
- TypeScript strict 모드 유지 (타입에 민감하다)
- Tailwind CSS 사용 (빠르다)
```

backend.mdc
```
Scope: api/**/*.ts
Rules:
- 라우팅에 Express.js 사용 (내가 자주 사용하는 것)
- RESTful API 규칙 따르기 (표준이 중요하다)
- async/await 사용 (콜백 지옥 없애기)
```

이런 규칙으로 Cursor는 추측을 멈추고 작동하는 코드를 제공하기 시작했다. 완전히 달라졌다.

## Step 6: 보상 거두기
프로젝트 규칙을 사용한 이후로 내 삶이 더 쉬워졌다. Cursor는 실수를 덜 하고, 내 스타일을 기억하며, 처음에 제대로 된 코드를 제공한다. 마치 정말로 듣는 주니어 개발자를 두는 것과 같다.

## Step 7: 프로젝트 규칙을 위한 팁
다음은 프로젝트 규칙을 마스터하기 위한 내 고된 경험에서 얻은 팁들이다.
- 규칙을 구체적으로 유지하기: 프론트엔드, 백엔드 등을 분리하라. 모든 것을 하나의 파일에 밀어넣지 마라.
- 정확한 범위 사용하기: React에는 .tsx, 백엔드에는 api/**/*.ts와 같이 필요한 곳에만 규칙을 적용하라.
- 일찍 테스트하기: 먼저 작은 코드 스니펫을 생성하여 Cursor가 규칙을 따르는지 확인하라.
- 필요에 따라 업데이트하기: 프로젝트가 변하면 규칙도 업데이트하라. 오래된 상태로 두지 마라.

## AI 코딩의 핵심
작동하지 않는 AI 코드에 짜증이 난다면, 해결책은 간단하다. 준비하고 통제하라. ChatGPT Voice로 계획하고, CodeGuide로 문서화하며, 스타터 킷으로 시작하고, .mdc 파일로 규칙을 설정하라. 이렇게 하면 Cursor는 좌절의 원인에서 최고의 코딩 친구로 바뀔 것이다.

이제 더 똑똑하게 코딩하고, 더 열심히 코딩하지 말자. 그리고 만약 나처럼 여전히 냅킨에 끄적이고 있다면, 그것을 받아들이라 - 그것이 바로 차이를 만드는 인간적인 터치다.
