#nodejs #concurrency #libuv 

웹 애플리케이션 성능을 이야기할 때, "빠르다"는 말은 여러 의미를 가질 수 있습니다. 서버 응답이 빠르다거나, 메모리를 적게 사용한다거나, 데이터베이스 쿼리가 매우 빠르다는 등의 의미죠. 하지만 Node.js가 "빠르다"고 불리는 근본적인 이유가 뭘까요? 바로 동시성(Concurrency)입니다. 멀티스레딩이나 JavaScript 엔진의 순수 속도가 아니라(물론 이것도 도움이 됩니다), 작업을 막지 않고 처리하는 방식이 핵심입니다.

## "속도"의 오해: Node.js에서 "빠르다"의 진짜 의미
"Node.js는 빠르다"라는 말을 들으면 오해하기 쉽습니다. C++나 Go 같은 컴파일 언어와 달리, Node.js는 CPU를 많이 사용하는 작업에서는 속도 경쟁에서 이기지 못합니다. 숫자 계산을 다른 언어보다 더 빨리 처리하는 것이 아니라는 뜻이죠.

Node.js의 진짜 강점은 많은 작업, 특히 입출력(I/O) 작업을 막힘 없이 동시에 처리할 수 있다는 점입니다. 수천 개의 스레드를 만들지 않고도 수천 명의 사용자를 처리할 수 있어서 확장성과 비용 측면에서 큰 이점이 있습니다.

이것이 왜 중요하고 어떻게 작동하는지 알아봅시다.

## Node.js의 단일 스레드 특성(그리고 왜 이것이 문제가 되지 않는지)
Node.js는 단일 스레드에서 실행됩니다. 즉, 요청마다 새 스레드를 생성할 수 있는 Java나 C#과 달리, 애플리케이션에는 하나의 주요 실행 흐름만 있다는 뜻입니다.

언뜻 보면 이것은 제한처럼 보입니다. 어떻게 단일 스레드가 수백 또는 수천 명의 사용자를 동시에 처리할 수 있을까요?

비결은 바로 Node.js가 이벤트 기반, 비동기 I/O 모델을 사용한다는 것입니다.

## 실생활 비유: 카페
바리스타 한 명이 있는 카페를 상상해보세요.
1. 블로킹 방식(전통적인 멀티스레드 시스템처럼)에서는, 바리스타가 주문을 받고 커피가 내려질 때까지 가만히 서서 기다립니다. 그 후에야 다음 손님을 응대합니다. 커피 내리는 데 3분이 걸린다면, 그 3분은 그냥 손실됩니다.
2. Node.js 방식에서는, 바리스타가 주문을 받고, 커피를 내리기 시작한 다음, 커피가 만들어지는 동안 바로 다음 손님의 주문을 받습니다. 커피가 준비되면, 손님 이름을 불러 알려줍니다.

이것이 동시성입니다. 바리스타가 커피를 더 빨리 만드는 것이 아니라, 기다리는 시간을 낭비하지 않고 더 많은 손님을 응대하는 것이죠.

## 이벤트 루프: 동시성의 핵심
Node.js의 핵심에는 이벤트 루프(Event Loop)라는 것이 있으며, 이것이 동시성을 가능하게 하는 엔진입니다.

작동 원리는 다음과 같습니다:
1. Node.js가 요청을 받습니다(예: 데이터베이스 쿼리나 파일 읽기).
2. 시간이 오래 걸리는 I/O 작업인 경우, Node.js는 이를 시스템에 위임합니다(libuv를 통해 백그라운드 스레드 사용).
3. 시스템이 해당 작업을 처리하는 동안, Node.js는 다른 코드 실행을 계속합니다.
4. I/O 작업이 완료되면, 이벤트 루프가 결과를 가져와 콜백을 실행하거나 프로미스를 해결합니다.

메인 스레드는 절대 막히지 않습니다. 항상 유용한 작업을 수행합니다 - 이벤트 처리, 콜백 실행, 새로운 연결 처리 등.

이런 설계 덕분에 Node.js는 수천 개의 동시 연결을 처리할 수 있습니다.

## libuv: 동시성의 숨은 영웅
Node.js는 이 모든 기능을 구현하기 위해 libuv라는 라이브러리를 사용합니다. 이 라이브러리는 다양한 플랫폼에서 비동기 I/O 작업을 추상화해줍니다.

libuv가 관리하는 것들:

- 파일 시스템 접근
- DNS 해석
- 네트워크 통신
- 작업 분산을 위한 스레드 풀
- 타이머 및 비동기 콜백

Node.js가 작업을 위임할 때, 실제로 뒤에서 마법을 부리는 것은 libuv입니다. Node.js 코드는 단일 스레드이지만, libuv는 내부적으로 스레드 풀을 사용하여 비동기 작업을 실행합니다.

그래서 Node는 단일 스레드이지만 libuv 덕분에 많은 일을 동시에 할 수 있는 것입니다.

## 동시성 vs 병렬성: 중요한 차이점
이 두 용어는 자주 혼용되지만, 실제로는 다릅니다:

- 동시성은 한 번에 많은 일을 처리하는 것입니다(모든 작업을 즉시 완료하지 않고 여러 작업을 번갈아가며 처리하는 것).
- 병렬성은 말 그대로 여러 일을 정확히 동시에 처리하는 것입니다(여러 CPU가 동시에 각각 다른 작업을 처리하는 것).

Node.js는 병렬성이 아닌 동시성에 최적화되어 있습니다. 그리고 이것은 웹 개발에 딱 맞습니다! 웹 애플리케이션은 주로 I/O 작업(API 호출, 데이터베이스 쿼리, 파일 시스템 접근 등)을 다루기 때문에, 성능에 정말 중요한 것은 동시성입니다.

## Async/Await와 Promise의 강력함
전통적인 블로킹 코드는 이렇게 생겼습니다:

```javascript
const data = fs.readFileSync('file.txt');
console.log(data.toString());
```

이 코드는 파일을 다 읽을 때까지 모든 작업을 중단시킵니다.
Node.js의 비동기 방식에서는

```javascript
const fs = require('fs').promises;

async function readFile() {
  const data = await fs.readFile('file.txt');
  console.log(data.toString());
}

readFile();
```

이제 Node.js는 파일 읽기가 완료될 때까지 기다리는 동안 다른 작업을 계속 처리할 수 있습니다.

Async/await는 프로미스를 더 쉽게 사용할 수 있게 해주는 문법일 뿐이지만, 비동기 프로그래밍을 훨씬 간결하고 이해하기 쉽게 만들어 줍니다. 이벤트 루프와 결합하면, 확장성이 뛰어나면서도 코드 가독성이 좋은 시스템을 갖게 됩니다.

## 실제 예시: 동시성이 빛나는 순간들

### **시나리오 1: API 서버 개발**
데이터베이스를 조회하고, 파일을 읽고, 외부 API를 호출하는 REST API를 만든다고 가정해 봅시다. 블로킹 방식의 언어를 사용한다면, 서버는 요청마다 별도의 스레드가 필요합니다. 이는 리소스를 많이 소모합니다.

**Node.js에서는..**
- 이 모든 작업이 동시에 처리될 수 있습니다.
- 데이터베이스나 네트워크 응답을 기다리는 동안 스레드가 블록되지 않습니다.
- 최소한의 리소스로 수천 개의 동시 API 호출을 처리할 수 있습니다.

### **시나리오 2: 실시간 채팅 앱**
카카오톡이나 슬랙 같은 실시간 앱은 많은 사용자에게 빠르고 일관된 응답이 필요합니다.
WebSocket 연결을 사용하면, Node.js는 수천 개의 열린 연결을 관리하고 메인 스레드를 막지 않으면서 새로운 메시지나 '입력 중' 표시기 같은 이벤트에 응답할 수 있습니다.

## 그렇다면 — Node.js는 항상 빠른가?
완벽한 기술은 없습니다. Node.js의 동시성 모델은 I/O 위주 작업에는 뛰어나지만, CPU를 많이 사용하는 작업에는 적합하지 않습니다.
앱이 무거운 계산(예: 영상 처리, 암호화, 머신러닝)을 수행하면, 메인 스레드를 막아 전체 성능을 저하시킬 수 있습니다.
**해결책? 작업 분산!**
- CPU 집약적 작업을 분산하기 위해 워커 스레드(Node.js v10.5+ 부터 지원)를 사용하세요.
- 백그라운드 워커에게 처리를 위임하기 위해 RabbitMQ 같은 메시지 큐 시스템을 활용하세요.
- 극도의 성능이 필요한 경우 C++ 애드온을 검토하세요.

## 동시성 사용 시 흔한 실수들
동시성은 강력하지만, 까다로운 문제를 일으킬 수도 있습니다:
### 1. 콜백 지옥
프로미스와 async/await 이전에는 중첩된 콜백이 코드를 복잡하게 만들었습니다. 다행히도, 현대적인 문법이 이 문제를 대부분 해결했습니다.

```javascript
// 구식 방식 - 복잡함
getUser(id, function(user) {
  getPosts(user.id, function(posts) {
    getComments(posts[0].id, function(comments) {
      console.log(comments);
    });
  });
});
```

### 2. 처리되지 않은 프로미스 오류
비동기 코드에서 오류 처리를 잊으면 앱이 충돌하거나 조용히 실패할 수 있습니다.

```javascript
// 이것을 꼭 기억하세요
readFile().catch(console.error);
```

### 3. 이벤트 루프 차단
다음과 같은 CPU 집약적 함수를 호출하면 동시성의 이점이 사라집니다:

```javascript
function bigLoop() {
  for (let i = 0; i < 1e9; i++) {} // 이벤트 루프를 차단합니다!
}

bigLoop(); // 안 좋은 예시!
```

항상 기억하세요.
CPU를 많이 사용하는 작업이라면, 분산 처리할 방법을 찾아야 합니다.

## 동시성을 더 강화하는 최신 기능들
Node.js는 계속 발전하고 있습니다. 다음은 동시성을 더 강화하는 몇 가지 최신 기능입니다:
### 1. 워커 스레드
Node.js에서 진정한 멀티스레딩을 구현합니다. 이제 메인 이벤트 루프를 막지 않고 CPU 집약적인 작업을 별도 스레드로 분산할 수 있습니다.

```javascript
const { Worker } = require('worker_threads');

new Worker('./myWorker.js'); // 다른 스레드에서 실행됩니다
```

### 2. 클러스터 모듈
여러 CPU 코어를 활용해 확장성을 높입니다. 애플리케이션을 여러 자식 프로세스로 나누어 하드웨어 자원을 최대한 활용할 수 있습니다.

### 3. 스트리밍 API
Node.js는 대용량 파일을 메모리에 완전히 로드하지 않고도 효율적으로 처리할 수 있게 해줍니다.

```javascript
fs.createReadStream('largefile.txt').pipe(res);
```

## 그래서, Node.js가 정말 빠른 이유는?

지금까지 살펴본 내용을 정리해 보겠습니다.

Node.js가 빠른 이유.
- I/O 작업에서 절대 멈추지 않습니다.
- 이벤트 기반 방식으로 단일 스레드에서 수천 개의 연결을 처리합니다.
- libuv와 이벤트 루프가 모든 비동기 작업을 효율적으로 관리합니다.
- 현대적인 JavaScript(async/await)로 비동기 코드 작성이 훨씬 쉬워졌습니다.
- 모든 요청마다 새 스레드를 만드는 오버헤드를 피합니다.
- 필요할 때 워커 스레드와 클러스터링으로 진정한 병렬 처리도 가능합니다.

이러한 이유로 넷플릭스, 라인, 카카오, 네이버와 같은 기업들도 성능이 중요한 시스템에 Node.js를 활용하고 있습니다.
